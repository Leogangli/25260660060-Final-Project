# 01 任务定义：月度财务关账与管理报告

## 1.1 任务概述

**任务名称**：月度财务关账 + 三表生成 + 异常检测 + 管理层月度报告（FinClose 月度循环）

**目标用户**：中小型企业的财务总监（主要用户）与财务经理（操作用户）。本人即目标用户，需求描述来自真实岗位实践。

**业务背景**：每月结账周期，财务团队需要把 ERP 导出的试算平衡表（TB）加工成三大报表，识别异常波动，并向管理层提交月度分析报告。该任务每月重复、阶段间有严格依赖、中间经常因数据返工而中断、且需要留痕备查——是典型的长程工作流场景。

## 1.2 现有（人工）流程与痛点

1. 每月 1–3 日：会计从 ERP 导出上月 TB（Excel），人工检查借贷平衡与科目映射；
2. 每月 3–5 日：在 Excel 模板中编制资产负债表、利润表、现金流量表（简表）；
3. 每月 5–7 日：财务经理手工计算同比/环比、毛利率、周转类指标，凭经验圈出异常；
4. 每月 7–8 日：撰写月度管理报告（Word/PPT），CFO 审阅、返修、定稿归档。

痛点：重复劳动量大；异常识别依赖个人经验、口径不一；数据返工后所有下游步骤推倒重来；报告版本与数字来源缺乏系统化留痕。

## 1.3 阶段、依赖与重复触发条件

| # | 阶段 | 类型 | 依赖 | 输入 | 产出 |
|---|------|------|------|------|------|
| S0 | 触发与摄取 ingest | 确定性代码 | 定时或新文件事件 | 当月 TB CSV、科目映射表、上月归档状态 | 标准化 TB（内部表）、输入哈希 |
| S1 | 数据质检 QC | 确定性代码 | S0 | 标准化 TB | QC 报告（借贷平衡、未知科目、余额方向、必填项） |
| S2 | 关账检查 close-check | LLM + 规则 | S1 通过 | TB、检查清单 | 关账检查清单（折旧/摊销/应计/往来异常提示） |
| S3 | 报表生成 statements | 确定性代码 | S1 | TB、映射表 | 资产负债表、利润表（Markdown + CSV） |
| S4 | 指标与异常检测 analysis | 确定性计算 + LLM 归因 | S3 | 本期 + 历史期间指标 | 指标表、异常清单（值/阈值/偏差/初步归因） |
| S5 | 报告撰写 report | LLM | S4 | 异常清单、报表 | 管理层月度报告草稿 |
| S6 | 独立核验 verify | 独立 LLM（Critic）+ 确定性重算 | S5 | 报告草稿、原始 TB、指标表 | 核验意见（逐条数字核对结果、问题清单） |
| S7 | 人工批准 approval | 人工门 | S6 通过或修订收敛 | 终稿、核验记录 | 批准记录（批准人、时间、意见） |
| S8 | 归档与基线更新 archive | 确定性代码 | S7 | 全部产物 | 版本化归档、更新环比基线、注册下期触发 |

**依赖关系**：S1 是硬门禁（QC 不过则停止并上报，不进入下游）；S5–S6 构成有界修订循环（最多 2 轮，不收敛则升级人工）；S7 之前任何产物不得对外发布。

**重复触发条件**：① 定时：每月 1 日 06:00（cron）；② 事件：新 TB 文件落盘 / 上游数据修正后重跑（输入哈希变化触发，仅失效下游阶段）。

**输入与允许使用的来源**：TB CSV、科目映射表、历史归档（`runs/` 与 `archive/`）。本项目一律使用 `data/sample/` 下的合成数据，不允许引入真实公司数据。

**信息截止时点**：每次运行锁定 `period_end`（如 2026-10-31）。所有分析与报告只允许使用 ≤ period_end 的数据；数据访问层按 period 过滤，单元测试验证 Agent 无法读到晚于当前期间的数据行（防未来信息泄露）。

## 1.4 工作产出与验收标准

**产出物**：① 三大报表（简表）；② 异常清单（每条含指标值、阈值、偏差幅度、可能原因、建议跟进动作）；③ 管理层月度报告；④ QC/核验/批准全程记录。

**验收标准**：
1. 报表数字与 TB 重算结果 100% 一致（确定性回归测试）；
2. 报告引用的每个数字可溯源到 TB 行或指标表行（核验 Agent 抽检零错误）；
3. 预埋异常（样例数据 2026-10 的应收激增、存货积压、毛利率下滑、现金骤降）被全部检出；
4. 中断恢复测试：在 S4 后 kill 进程，重跑时 S0–S3 不重复执行；
5. 基线回归：任何提示词/代码改动须通过固定样例数据的 golden 测试方可采纳。

## 1.5 为什么需要持久化工作流，而非一次性脚本

- **月度重复**：任务每月发生，且依赖上月状态（环比基线、检查清单结论），单次脚本无法保留跨月上下文；
- **中断与返工是常态**：上游数据修正发生时，需要只重跑受影响的下游阶段而非全部重来；
- **人工审批跨天**：CFO 批准可能隔数小时至数天，运行必须能挂起并在批准后续跑；
- **审计留痕**：每期产物、核验意见、批准记录、配置版本需要可回溯、可回滚。
